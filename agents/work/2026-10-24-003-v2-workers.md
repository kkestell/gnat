# V2 coordination and dynamic workers

## Plan

`agents/plans/2026-10-24-003-v2-workers.md`

## Summary

Milestone three adds independently scheduled Claude workers in managed local
worktrees, authenticated MCP coordination, durable attributed messaging,
provisioning/removal recovery, and dynamic browser membership/history. The live
Claude test created two workers, received both replies, continued a worker in its
existing conversation, and removed the other while retaining history.

## Departures from the plan

- No functional scope departures. Kept the MCP transport small and stateless,
  using JSON responses rather than an SDK dependency or server notifications;
  recipient turns are driven by the existing core scheduler.

## Decisions

- Retain the existing execution lifecycle field and add membership/stage fields;
  this preserves earlier records while separating provisioning/removal from turns.
- A new ordinary message explicitly continues an interrupted/unavailable worker
  through a prerequisite check and its exact saved session. Delivered input is
  never replayed and a failed resume never silently starts a new conversation.
- Retry failed creation with the original request ID and retry refused removal
  with the original or a new request ID. Both retain identity and saved ownership;
  a collision discovered before allocation never grants resource ownership.
- Return stable allocated branch/path metadata immediately with the creation ID;
  events/snapshots expose subsequent provisioning and execution changes.
- Bound runtime orientation to 50 team records and a queued-message count, and
  MCP inspection to at most 100 events with an 8,000-byte preview per event.
  Full transcripts remain in SQLite and the browser.

## Review outcome

- Review confirmed a continuation race: direction accepted while worker
  interruption was still settling could remain queued. Presented the finding
  and fixed it under the explicit autonomous kauto request. `send_message` now
  waits for the target worker's cancellation settlement before continuing its
  exact saved session; removal continues rejecting new messages immediately.
  A gated cancellation regression covers immediate direction and request replay.

## Manual verification

1. `GNAT_LIVE_TEST=1 go test ./internal/v2/daemon -run TestLiveCoordination -v -timeout 10m`
   passed with installed/authenticated Claude Code 2.1.310. The orchestrator
   created two workers, both sent ordinary replies through Gnat MCP, one replied
   to further direction in its existing session, and the other was removed.
   All work used disposable local repositories without GitHub or a remote.
2. Verified launch-specific configuration against the official
   [Claude CLI reference](https://code.claude.com/docs/en/cli-reference),
   [Claude MCP documentation](https://code.claude.com/docs/en/mcp), and
   [MCP Streamable HTTP specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports).
   Adapter fixtures confirm MCP header injection, runtime instructions, and
   authenticated sender display without rewriting project/global configuration.

3. Built `/tmp/gnat-m3-browser/gnat` directly from `cmd/gnat` and used
   `/tmp/gnat-m3-browser/setup.py` to launch a detached daemon in a disposable
   committed repository with isolated XDG state/config. Then ran
   `node /tmp/gnat-m3-browser/check.cjs` with Playwright Chromium. It created two
   real Claude workers through browser chat, inspected live worker transcripts,
   reloaded and compared history, reset the orchestrator while retaining the
   team, removed one worker, and inspected its retained transcript. Desktop
   (1440×960) and mobile (390×844) screenshots were visually inspected; worker
   inspection and chat remained accessible with no page errors. The script
   stopped its detached daemon afterward. Playwright was installed only in the
   temporary verification directory; repository dependencies were unchanged.
