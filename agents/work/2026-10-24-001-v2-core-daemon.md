# V2 core records and daemon entry

## Plan

`agents/plans/2026-10-24-001-v2-core-daemon.md`

## Summary

Milestone one is implemented. The native entry point opens persistent workspaces
through a detached, locked daemon and an embedded browser page. Registration
atomically stores workspace/swarm/orchestrator/conversation identities and four
creation events, without touching v1 state or the original checkout.

## Departures from the plan

None. The browser page deliberately reports a pending orchestrator: execution,
chat, worker lifecycle, and event streaming remain subsequent milestones.

## Decisions

- Promote the existing `golang.org/x/sys` dependency to direct use for the daemon
  lifetime lock; no new dependency or provider integration was needed.
- Use a generation-checked authenticated HTTP stop rather than signalling the
  saved PID, so a stale descriptor cannot stop an unrelated process.

## Manual verification

The native binary was built with `go build -o <temp>/gnat ./cmd/gnat` and run
against disposable committed repositories with isolated `XDG_STATE_HOME` and
`XDG_CONFIG_HOME`. Reproduce the lifecycle checks automatically with:

```sh
go test ./internal/v2/daemon -run TestDetachedDaemonLifecycle -count=1
```

The separate native CLI smoke run confirmed a missing-config error, then three
concurrent `gnat --no-open` launches from root/subdirectory/symlink selecting the
same URL. Fetching that URL after launchers exited returned the workspace page.
A temporary PATH-local `open` executable returning status 17 confirmed default
`gnat` still prints the usable URL and reports browser failure. `gnat daemon stop`
followed by `gnat --no-open` retained the swarm identity. All test daemons were
stopped afterward.
