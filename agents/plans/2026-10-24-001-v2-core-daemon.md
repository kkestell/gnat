# V2 core records and daemon entry

## Goal

Implement milestone one of `agents/gnat-v2-spec.md`: invoking `gnat` in a
committed local checkout opens one persistent swarm through one per-user daemon,
without Docker or GitHub. Preserve v1 data. Harness execution and chat remain
milestone two.

## Related code

- `cmd/gnat/main.go` currently dispatches to the v1 command surface.
- `internal/state/` and `internal/recorded/` own incompatible v1 data.
- `internal/web/` embeds the v1 dashboard, which assumes container agents.
- `go.mod` already supplies SQLite, YAML, Cobra, and Unix process primitives.

## Decisions

- Put the new runtime in `internal/v2/{entry,workspace,store,daemon}` so v1
  packages and data remain intact while subsequent milestones replace them.
  Switch the installed entry point to the minimal v2 commands immediately;
  obsolete build/distribution cleanup remains milestone six.
- Use `$XDG_STATE_HOME/gnat/v2` (default `~/.local/state/gnat/v2`) for SQLite
  and a private runtime directory containing the daemon lock and descriptor.
  SQLite schema versions are explicit and unknown versions fail closed.
- Identify a workspace by its canonical checkout root; save the canonical Git
  common directory separately. Distinct linked user worktrees remain distinct.
  Discovery only reads Git, rejects bare/uncommitted repositories, and makes no
  network calls. Future managed worker ownership will use saved agent paths.
- Read required orchestrator settings from `$XDG_CONFIG_HOME/gnat/config.yaml`
  (default `~/.config/gnat/config.yaml`) only when creating a swarm. Save resolved
  settings, a pending orchestrator, an initial conversation, and creation events
  in one transaction. Do not probe harnesses or claim readiness in this milestone.
- Hold an advisory lock throughout daemon lifetime, start it in a detached
  session, and verify its private generation/token descriptor through a readiness
  handshake. Bind an ephemeral IPv4 loopback port; authenticate CLI mutations
  with the runtime token and validate HTTP Host and Origin.
- Embed a small read-only HTML workspace switcher at `/swarms/{id}` and expose
  swarm snapshots with a committed sequence cursor. The v1 React dashboard is
  not adapted before there are v2 turns to display.

## Test plan

- Real temporary Git repositories: root/subdirectory/symlink identity, linked
  worktrees, dirty checkout preservation, bare and unborn rejection.
- SQLite: reopen persistence, concurrent registration uniqueness, transactional
  creation/events, schema rejection, and preservation of a v1 sentinel.
- HTTP: independent swarm routes, snapshots, missing workspaces, invalid Host,
  cross-origin mutations, and missing credentials.
- Real macOS subprocesses: concurrent launches share a daemon and swarm, distinct
  workspaces share the daemon, stale descriptor recovery, stop/restart preserves
  identities, and terminal-independent process lifetime.

## Implementation plan

1. Add workspace discovery and configuration/SQLite records with focused tests.
2. Add daemon ownership, authenticated discovery/start/stop client, HTTP routes,
   and embedded browser page; test lifecycle and HTTP boundaries.
3. Add minimal v2 CLI and switch `cmd/gnat/main.go`; cover flags and errors and
   exercise the built binary in disposable repositories on macOS.
4. Update current architecture, repository instructions, README, setup/usage,
   and plugin documentation to distinguish landed foundation from v1 and later
   v2 milestones. Record validation and limitations in the work log.
