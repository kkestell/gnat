# V2 coordination and dynamic workers

## Goal

Implement milestone three: the original-checkout Claude orchestrator creates,
messages, inspects, interrupts, and removes workers in separate local worktrees.
Agents coordinate through authenticated MCP and ordinary durable messages; the
browser follows dynamic membership and worker transcripts.

## Related code

- `internal/v2/store/`: SQLite records, transactional messages and ordered events.
- `internal/v2/core/`: neutral adapter, scheduling and execution controls.
- `internal/v2/harness/claude.go`: local launch and exact session continuation.
- `internal/v2/daemon/`: shared HTTP service and embedded browser assets.
- `agents/gnat-v2-spec.md` sections 6–9, 12–13, and milestone three.

## Decisions

- Keep the existing execution lifecycle and add a separate membership/provisioning
  dimension. Schedule independently by agent ID while swarm controls affect the
  whole team. Worker failures notify the orchestrator through the same queue;
  successful turn endings do not imply task completion or send automatic replies.
- Extend SQLite in place with sender/recipient attribution, saved worker defaults,
  base commit and provisioning stages. Request IDs are scoped to caller identity;
  asynchronous creation returns a stable agent ID immediately. Restart reconciles
  provisioning and removal, retaining work and surfacing failures without forcing Git.
- Allocate immutable-ID branches under `gnat/<swarm>/<agent>` outside the original
  checkout, resolving the requested base once. Remove registered worktrees with
  ordinary `git worktree remove` and branches with `git branch -d`; refusals leave
  visible resources for resolution and retry. Never reset branches or delete dirty work.
- Provide a small stateless JSON-response Streamable HTTP MCP endpoint with the
  six specified tools, role-specific discovery, strict argument decoding, and
  ephemeral per-agent bearer bindings. Browser actions use the same core service;
  agent credentials cannot reach browser/CLI authority or select another sender/swarm.
- Supply launch-scoped Claude MCP configuration and factual identity/team context
  without changing global settings, project instructions, or native delegation.
  Load optional `workers` settings at swarm creation, filling missing values from
  the saved orchestrator settings; per-creation overrides resolve and persist.
- Extend the existing embedded DOM UI, keeping the orchestrator sidebar and adding
  worker cards, metadata, conversation history, and inspection of removed agents.
  Keep coordination policy and Git integration in ordinary agent tools/messages.

## Test plan

- Schema migration and transactional attribution, per-agent FIFO, request replay,
  role/scope checks, removal cancellation, history bounds, reset team continuity.
- Temporary real Git repos: base selection, dirty original preservation, worktree
  ownership, safe removal refusals, and provisioning recovery.
- Injected adapters: two concurrent workers, follow-up delivery without polling,
  worker failure notification, interruption isolation, stop/resume and orderly close.
- HTTP MCP initialization/discovery/calls, invalid credentials/arguments/origins,
  dynamic snapshots/event replay, and launch-specific Claude configuration fixtures.
- Build and focused Go/race tests; live disposable-repository Claude coordination
  if authenticated Claude is installed. Record concrete limits if unavailable.

## Implementation plan

1. Extend store schema, agent/message/history operations and transitions.
2. Add worktree allocation/removal and per-agent core lifecycle/scheduling.
3. Add MCP endpoint and Claude launch bindings/instructions.
4. Add dynamic worker UI and HTTP dispatch through shared services.
5. Update architecture, repository instructions, spec status, README, operating
   documentation and plugin source-build guidance; validate and record work.
